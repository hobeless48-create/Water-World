# แอปจัดการสต็อกร้านผลิตน้ำดื่ม (water_world)

แอปพลิเคชันจัดการคลังสินค้าและสต็อกสำหรับร้านผลิตน้ำดื่ม พัฒนาด้วย **Flutter + SQLite (`sqflite`)** รองรับการทำงานบนเครื่องแบบ Offline-first และใช้ภาษาไทยเป็นหลัก

ระบบช่วยจัดการวัตถุดิบ การผลิต การขาย การตรวจสอบประวัติสต็อก รวมถึงการวิเคราะห์ปริมาณวัตถุดิบและแจ้งเตือนเมื่อควรสั่งซื้อเพิ่ม

## R1 — ระบบจัดการคลังสินค้าและการผลิต

### ฟังก์ชันที่ทำแล้ว

- **คลังสินค้า**: แสดงปริมาณสต็อกคงเหลือ แยกแท็บวัตถุดิบและสินค้าสำเร็จรูป
- **รับเข้าวัตถุดิบ**: บันทึกจำนวน ต้นทุนต่อหน่วย และหมายเหตุ
- **บันทึกการผลิต**: ตัดวัตถุดิบตามสูตรการผลิต (BOM) และเพิ่มสินค้าสำเร็จรูปโดยใช้ Database Transaction
- **ตรวจสอบวัตถุดิบก่อนผลิต**: แสดงจำนวนที่ต้องใช้ จำนวนที่มีอยู่ และจำนวนที่ขาด พร้อมป้องกันการยืนยันการผลิตเมื่อวัตถุดิบไม่เพียงพอ
- **ขายและส่งสินค้า**: ตัดสต็อกสินค้าสำเร็จรูป พร้อมบันทึกชื่อลูกค้าเพื่อรองรับการขายแบบ B2B ในอนาคต
- **ปรับยอดสต็อก**: เพิ่มหรือลดจำนวน พร้อมระบุเหตุผล เช่น ตรวจนับสต็อกจริงหรือสินค้าเสียหาย
- **ประวัติสต็อก**: บันทึกการเคลื่อนไหวของสินค้า พร้อมกรองประเภทธุรกรรม
- **ป้องกันสต็อกติดลบ**: ตรวจสอบจำนวนก่อนทำรายการ และใช้ Rollback เมื่อการผลิตไม่สามารถดำเนินการได้ครบถ้วน

## R2 — ระบบแจ้งเตือนสต็อกและแนะนำการสั่งซื้อ

### ฟังก์ชันที่ทำแล้ว

- **Stock Alert**: แสดงสถานะความเสี่ยงของวัตถุดิบ แบ่งเป็นปกติ เตือนสต็อกต่ำ และวิกฤต
- **คำนวณ Safety Stock**: คำนวณปริมาณสต็อกสำรองจากระดับการให้บริการ ความผันผวนของการใช้วัตถุดิบ และระยะเวลารอสินค้า
- **คำนวณ Reorder Point**: คำนวณจุดสั่งซื้อจากอัตราการใช้เฉลี่ยต่อวัน ระยะเวลารอสินค้า และปริมาณสต็อกสำรอง
- **วิเคราะห์การใช้วัตถุดิบ**: ใช้ข้อมูลย้อนหลัง 30 วันเพื่อคำนวณอัตราการใช้เฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน
- **แนะนำจำนวนที่ควรสั่งซื้อ**: คำนวณปริมาณสั่งซื้อที่แนะนำ เพื่อให้สต็อกกลับไปถึงระดับเป้าหมาย
- **กำหนดนโยบายสต็อก**: ตั้งค่าระยะเวลารอสินค้า (Lead Time), จำนวนวันที่ต้องการสำรองสต็อก (Target Days), ระดับการให้บริการ (Service Level), Safety Stock และจุดสั่งซื้อขั้นต่ำได้
- **สร้างรายการสั่งซื้อ**: เลือกวัตถุดิบและจำนวนที่ต้องการสั่งซื้อจากหน้าจอแจ้งเตือน แล้วบันทึกเป็นรายการสั่งซื้อแบบร่าง (Draft)
- **ดูรายการสั่งซื้อที่บันทึกไว้**: แสดงรายการสั่งซื้อย้อนหลังและเปิดดูรายละเอียดของแต่ละรายการ เช่น วันที่สร้าง วัตถุดิบ จำนวน ต้นทุนต่อหน่วย และยอดรวม

### หลักการคำนวณ

**1. Safety Stock — ปริมาณสต็อกสำรอง**

`Safety Stock = Z × SD × √Lead Time`

- `Z` คือค่าที่สัมพันธ์กับระดับการให้บริการที่ต้องการ
- `SD` คือส่วนเบี่ยงเบนมาตรฐานของอัตราการใช้วัตถุดิบต่อวัน
- `Lead Time` คือระยะเวลารอสินค้า

**2. Reorder Point — จุดสั่งซื้อ**

`Reorder Point = Average Daily Usage × Lead Time + Safety Stock`

**3. Suggested Order Quantity — จำนวนที่แนะนำให้สั่งซื้อ**

`Suggested Quantity = max(0, Target Stock − Current Stock)`

ระดับสต็อกเป้าหมายคำนวณจากอัตราการใช้เฉลี่ยต่อวัน จำนวนวันที่ต้องการสำรอง และ Safety Stock

ระบบสามารถใช้ค่าที่ผู้ใช้กำหนดเองสำหรับ Safety Stock และจุดสั่งซื้อขั้นต่ำได้ หากไม่ได้กำหนด ระบบจะคำนวณจากข้อมูลการใช้วัตถุดิบ

## ฐานข้อมูล

| ตาราง | หน้าที่ |
|---|---|
| `items` | เก็บข้อมูลวัตถุดิบและสินค้าสำเร็จรูป รวมถึงปริมาณคงเหลือและนโยบายสต็อก |
| `recipes` | เก็บสูตรการผลิต (BOM) ระบุว่าวัตถุดิบแต่ละชนิดต้องใช้เท่าใด |
| `production_batches` | เก็บข้อมูลเอกสารการผลิตและหมายเลข BATCH |
| `stock_transactions` | เก็บประวัติการเคลื่อนไหวของสต็อก เช่น รับเข้า ผลิต ขาย และปรับยอด |
| `purchase_orders` | เก็บรายการสั่งซื้อ สถานะเอกสาร รายการวัตถุดิบ และวันที่สร้าง |

### คอลัมน์สำคัญ

- `min_quantity` — ปริมาณขั้นต่ำหรือจุดสั่งซื้อที่กำหนดเอง
- `safety_stock` — ปริมาณสต็อกสำรองที่กำหนดเอง
- `reserved_quantity` — ปริมาณสินค้าหรือวัตถุดิบที่สำรองไว้สำหรับคำสั่งซื้อ R3
- `unit_cost` — ต้นทุนต่อหน่วยสำหรับการวิเคราะห์ต้นทุนใน R4
- `items_json` — รายละเอียดรายการวัตถุดิบที่บันทึกอยู่ในเอกสารสั่งซื้อ
- `created_at` — วันที่และเวลาที่สร้างรายการสั่งซื้อ

## ข้อมูลเริ่มต้นของระบบ

ระบบเตรียมข้อมูลตัวอย่างอัตโนมัติเมื่อเปิดแอปครั้งแรก ประกอบด้วย

**วัตถุดิบ**
- ขวด PET ขนาด 350, 600 และ 1,500 มล.
- ฝาเกลียว
- ฟิล์ม PVC
- ฟิล์ม PE

**สินค้าสำเร็จรูป**
- น้ำดื่มขนาด 350 มล.
- น้ำดื่มขนาด 600 มล.
- น้ำดื่มขนาด 1,500 มล.

ผู้ใช้งานต้องกำหนดสูตรการผลิตตามข้อมูลจริงในหน้าสูตรการผลิต ระบบไม่สร้างสูตรโรงงานหรือประวัติราคาซื้อสมมติ

## เทคโนโลยีที่ใช้

- **Flutter / Dart** — พัฒนาแอปพลิเคชัน
- **SQLite (`sqflite`)** — จัดเก็บข้อมูลภายในเครื่อง
- **Provider** — จัดการสถานะและข้อมูลของแอป
- **Offline-first** — รองรับการใช้งานโดยไม่จำเป็นต้องเชื่อมต่ออินเทอร์เน็ต

## โครงสร้างไฟล์หลัก

```text
lib/
├── data/
│   └── stock_repository.dart
├── providers/
│   └── inventory_provider.dart
├── screens/
│   ├── stock_alert_page.dart
│   ├── purchase_order_page.dart
│   └── purchase_order_history_page.dart
└── models.dart
```

- `stock_repository.dart` — ติดต่อฐานข้อมูลและดำเนินการเกี่ยวกับสต็อก
- `inventory_provider.dart` — จัดการสถานะสต็อก คำนวณความเสี่ยง และเรียกใช้ข้อมูลสั่งซื้อ
- `stock_alert_page.dart` — แสดงการแจ้งเตือนและความเสี่ยงของวัตถุดิบ
- `purchase_order_page.dart` — สร้างรายการสั่งซื้อ
- `purchase_order_history_page.dart` — แสดงรายการสั่งซื้อที่บันทึกไว้
- `models.dart` — คลาสข้อมูลที่ใช้ภายในระบบ

## R3 — ลูกค้าและคำสั่งซื้อขายส่ง

- เพิ่มและค้นหาลูกค้า ระบุจำนวน ราคาขาย และกำหนดส่ง
- ตรวจสินค้าพร้อมใช้ สูตรการผลิต และความต้องการวัตถุดิบรวม
- ประเมินระยะเวลาพร้อมส่งจากระยะเวลาจัดซื้อและผลิต ไม่ใช่การจัดตารางกำลังผลิตหรือขนส่ง
- สำรองสินค้าสำเร็จรูปและวัตถุดิบ บันทึกผลิต ยืนยันจัดส่ง หรือยกเลิกเพื่อคืนยอดสำรอง

## R4 — ภาพรวมสำหรับผู้จัดการ

- สรุปยอดวันนี้ สินค้าพร้อมส่งตามขนาด วัตถุดิบที่ต้องเติม และคำสั่งซื้อคงค้าง
- ดูยอดขาย การผลิต การจัดส่ง และการใช้วัตถุดิบ เลือกวันนี้ / 7 วัน / 30 วัน
- ประวัติราคาซื้อขวดจากใบรับสินค้าจริง ไม่ดึงราคาจากอินเทอร์เน็ตหรือใช้ราคาปัจจุบันแทนประวัติ
- บันทึกใบรับสินค้าพร้อมจำนวน ราคาซื้อ วันที่ ผู้จำหน่าย และเลขที่เอกสาร โดยเพิ่มสต็อกครั้งเดียว

## R5 — บัญชีผู้ใช้และบทบาท (ขอบเขตล่าสุด)

- สมัครสมาชิก เข้าสู่ระบบ ออกจากระบบ และกลับไปหน้าเข้าสู่ระบบ
- บัญชีใหม่เป็นผู้ใช้งานทั่วไปและเข้าใช้งานได้ทันที
- ทุกบัญชีที่เข้าสู่ระบบใช้ฟังก์ชันงานทั่วไปได้ เฉพาะผู้จัดการเท่านั้นที่เปิดภาพรวมและจัดการบัญชี/บทบาทได้
- ปุ่มจัดการบัญชีผู้ใช้บนหน้าภาพรวมเปิดรายชื่อจากฐานข้อมูล SQLite เพื่อแก้ไขบทบาท
- รหัสผ่านเก็บเป็นค่าแฮช PBKDF2 พร้อม salt
- ขอบเขตปัจจุบันไม่รวมการซิงก์ข้อมูลข้ามอุปกรณ์

## เริ่มใช้งานและตรวจสอบ

```sh
flutter pub get
flutter run
```

ใช้ Flutter SDK ที่รองรับเวอร์ชัน Dart ใน pubspec.yaml ฐานข้อมูลใหม่สร้างบัญชีสาธิตสำหรับการเรียน `admin` / `123456` บทบาทผู้จัดการ บัญชีนี้เป็นข้อมูลสาธิตที่เผยแพร่พร้อมโค้ด ต้องปรับการตั้งค่าบัญชีก่อนใช้งานกับข้อมูลจริง

```sh
flutter test
flutter analyze
flutter build apk --debug
```

ผลตรวจในเครื่องก่อนส่ง: ผ่าน 20 tests รวมการยกเลิก/บันทึก/ย้อนกลับ/แตะภายนอกหน้าต่างแก้บทบาท สร้าง APK สำเร็จ และ analyzer มีข้อเสนอแนะระดับ info 17 รายการ โดยไม่มี error หรือ warning
